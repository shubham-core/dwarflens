# DwarfLens Architecture & JSON Data Contracts

## 1. Overview
DwarfLens is a binary size, bloat attribution, and DWARF struct memory-layout analyzer with zero external runtime dependencies in its C++23 core engine.

- **Inputs:** Linux ELF64, WebAssembly (.wasm), macOS Mach-O (64-bit), Windows PE/COFF (64-bit).
- **Core Engine:** Safe cursor reads (`SpanReader`), interval attribution (`RangeMap`), two-pass DIE walker (`DwarfReader`), layout diagnostics and alignment repacker (`LayoutAnalyzer`), and diff calculator (`DiffEngine`).
- **Outputs:** Terminal tables, Markdown reports, and standardized JSON.

## 3. SaaS Ingestion & Privacy Boundary
- **Never Upload Binaries:** The binary analysis runs completely inside CI runners or developer machines.
- **Payload Ingestion:** The CI GitHub Action sends only the generated `BinaryAnalysis` JSON (capped at 5 MB) via an authenticated POST request to `/api/v1/analyses`.

---

## 4. Rate Limiting & Scaling Architecture
- **Edge IP Resolution:** Client IPs are extracted through trusted edge headers (`CF-Connecting-IP`, `True-Client-IP`, or the rightmost IP in `X-Forwarded-For`), neutralizing client-injected IP headers.
- **Rate Limit Bucketing:** Distinct rate buckets are enforced for OAuth (`auth-oauth`), dev-login (`auth-login`), share link operations (`share-read`, `share-create`), and analysis ingestion (`ingest`).
- **Distributed Coordination:** The reference implementation operates an in-memory sliding window store with active garbage collection. Multi-instance cluster deployments require a shared cache (e.g., Redis / Valkey) for globally synchronized rate enforcement.
